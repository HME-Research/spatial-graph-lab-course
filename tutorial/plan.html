Plan your toolkit

Decide five things before you ask an AI to write anything. Fill them in below: this page turns them into the prompt for a coding agent and for a chat assistant, and the other pages fill in your toolkit id.

What a toolkit contains

toolkits/<toolkit-id>/ toolkit.ts its name, its default design, the attributes every node / edge has README.md what it is for and how to try it (your tutor reads this) functions/ one Function per file: Reading room, Stacks… algorithms/ one analysis or transform per file designs/ example designs (.json), shown in Open example… assets/ optional: Rhino .3dm façade files lib/ optional: helper code shared by several algorithms

A complete example is toolkits/house/ (read it, never change it). The full guide is lab/docs/TOOLKITS.md in the repository.

Decide

DecisionRuleTip
Toolkit id (folder and branch name)lowercase letters, digits and -, starting with a letterMake it unique in the class with your initials, e.g. hk-library. Never rename it later.
Ideaone or two sentencesA building type or a design question.
Functionsone per room programmeStart with 3–6. Say what each should record (e.g. a Reading room records its seats).
Algorithmsan analysis reads and shows; a transform proposes changes you preview and ApplyStart with one or two. Write each as a rule you could explain in one sentence.
Example designa small design that uses your FunctionsThe checks run every algorithm on it, so keep it small.

Ids are forever. Designs store your Function ids and attribute names; projects store your toolkit id. Add new ones rather than renaming old ones.
