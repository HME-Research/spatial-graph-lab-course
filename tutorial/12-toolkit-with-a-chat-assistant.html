Developing method 2: use an AI chat assistant

A chat in the browser cannot see your files. You give it the toolkit kit, it gives you your folder as a zip, and you put the folder in place, check it, commit and push.

Before this page you need:

  • the course folder open in VS Code, with npm ci done (see Clone the repository);
  • your branch on GitHub and your prompt (see Start developing: set up).

Orange text like <your-toolkit-name> = replace it with your own. Grey buttons like Copy = something to click.

01

Check your branch

First, in VS Code's terminal.

 
git branch --show-current

toolkit/<your-toolkit-name>, not main.

It shows main
git switch toolkit/<your-toolkit-name>
I have no branch yet

Make it first: Make your branch and send it to GitHub.

02

Download the toolkit kit

The zip the chat reads.
Download the toolkit kit (.zip)
What is in it?

The AI's instructions (PROMPT.md), the toolkit guide, the Student API reference, a starter toolkit and the House example. The same kit is in the app: Guide › Toolkits & JSON › Make your own toolkit › Chat assistant.

03

Ask the chat

Attach the kit, send your prompt, download the zip.
  1. Open a new chat and attach the kit zipAny AI chat that accepts files, such as claude.ai, chatgpt.com or gemini.google.com.
  2. Send your promptFrom page 10 › Your prompt (filled in), or this one with the orange blanks filled in: 
    I've attached the Spatial Graph Lab toolkit kit. Read PROMPT.md and every file in it, then write my toolkit following it exactly. The folder name is exactly my toolkit name. Give me the folder <your-toolkit-name>/ as a zip; if you cannot make files, give every file in its own code block, headed by its path.

Toolkit name: ___
My idea: ___
Functions (and their attributes): ___
Algorithms: ___
Example design: ___
  3. Read its summaryAsk for changes now, in plain words.
  4. Download the zip it gives youIt lands in your Downloads folder.
Try the zip in the app first? (optional)

The same zip can also be uploaded in the app to try it: Welcome › Upload toolkit (.zip) (page 06). Then still put the folder in place here.

The chat refuses the zip, or gives code instead of a zip
  • Refuses the zip: unzip the kit and attach its .md files instead, or try another chat.
  • Code blocks instead of a zip: ask “Please give me the folder as a zip”. Still no zip? Try another chat, or ask your tutor.
04

Put the folder in place

Unzip, then drag the folder into toolkits.

Drag the folder that has toolkit.ts directly inside it. Unzipping often adds one more folder level. If you open the folder and see only one more folder, open that one: that is the folder to drag.

Windows

  1. File Explorer › Downloads: right-click the zip › Extract All… › Extract.
  2. Open the course's toolkits folder in a second window: in VS Code's explorer, right-click toolkits › Reveal in File Explorer.
  3. Drag the folder with toolkit.ts directly inside into toolkits.

macOS

  1. Finder › Downloads. Safari often unzips by itself; otherwise double-click the zip.
  2. Open the course's toolkits folder in a second window: in VS Code's explorer, right-click toolkits › Reveal in Finder.
  3. Drag the folder with toolkit.ts directly inside into toolkits.

The folder's name must be exactly <your-toolkit-name>. The zip's own name does not matter.

Something went wrong?
  • My folder is inside another folder of the same name
  • The folder has another name than my toolkit name
05

Check it

The same checks GitHub runs on your branch.

 
npm run check:toolkit -- -t <your-toolkit-name>

You should see, at the end

PASSED: toolkit "u123-hk-house" is ready.
The last line counts. FAILED: …? Copy the whole red message into the chat and ask: “Fix exactly this and give me only the files you changed.”
npm run typecheck

the prompt again, with no red error lines.

What do the two checks do?

check:toolkit loads your toolkit as the app does and runs every algorithm on your example design. typecheck checks the code for mistakes.

06

Try it in the app

Run the app with your toolkit.

 
npm run dev

Open http://localhost:5173/?toolkit=<your-toolkit-name> › Open example… › your toolkit's design. Run your analyses in Analyse and transforms in Transform.

The terminal is busy while the app runs. Use a second terminal (+) for the next step; Ctrl+C stops the app.

07

Commit and push

Only your folder.

 
git add toolkits/<your-toolkit-name>
git status

Under “Changes to be committed” (green): only files in toolkits/<your-toolkit-name>/. Anything else there? Don't commit: put it back first.

git commit -m "feat(<your-toolkit-name>): first version of my toolkit"

Git says “Please tell me who you are”? Do this once, then commit again.

git push

toolkit/<your-toolkit-name> -> toolkit/<your-toolkit-name>.

PASSED, the push went through, and a green ✓ appears beside your latest commit on GitHub.

08

Later changes

Give the chat your current files; replace what it changes, one file at a time.
  1. Commit firstSo that you can always go back (step 07).
  2. Ask the chatAttach the files you changed (or your whole folder as a zip) and ask it to give back only the files it changed.
  3. Replace file by fileIn VS Code, open each file it changed and replace its whole text. Never unzip a new folder next to the old one.
  4. See what changed, then check
    git diff --stat

    only files in your folder.

    Then check (step 05), commit and push.

A design you drew in the app as one of your toolkit's designs: Where your designs go.

09

All the commands, as one list

For reference only: run them one at a time from the steps.

No Copy button here on purpose: lines starting with # are things you do by hand, and npm run dev keeps running.

git status
# the first line must say "On branch main"; on another branch? run git switch main first
git pull
git switch -c toolkit/<your-toolkit-name>
git commit --allow-empty -m "chore(<your-toolkit-name>): start my toolkit"
git push -u origin toolkit/<your-toolkit-name>
# this puts your branch on GitHub: you must see * [new branch]
# unzip: the folder must end up at toolkits/<your-toolkit-name>/ (toolkit.ts directly inside it)
# first time on this computer only:
npm ci
npm run check:toolkit -- -t <your-toolkit-name>
# it must end with PASSED: toolkit "<your-toolkit-name>" is ready.
npm run typecheck
npm run dev
# try it at http://localhost:5173/?toolkit=<your-toolkit-name> (or the address npm run dev prints), then stop the server (Ctrl+C)
git add toolkits/<your-toolkit-name>
git status
git commit -m "feat(<your-toolkit-name>): first version of my toolkit"
git push
