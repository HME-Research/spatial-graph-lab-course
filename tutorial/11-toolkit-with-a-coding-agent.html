Developing method 1: use an AI agent

The agent (Codex, Claude Code or GitHub Copilot in Agent mode) writes your folder inside VS Code. You describe it, review it, try it and push.

Before this page you need:

  • the course folder open in VS Code, with npm ci done (see Clone the repository);
  • your branch on GitHub and your prompt (see Start developing: set up).

Orange text like <your-toolkit-name> = replace it with your own. Grey buttons like Copy = something to click.

01

Check your branch You do this

First, before you send anything to the agent.

 
git branch --show-current

toolkit/<your-name-tag>, not main. VS Code's bottom left shows the same.

It shows main

Go to your branch (no -c: it exists already):

git switch toolkit/<your-name-tag>
I have no branch yet

Make it first: Make your branch and send it to GitHub.

02

Start your agent You do this

Open its panel, and set what it may do without asking.
  • GitHub Copilot: the Chat view, set to Agent.
  • Codex: the Codex panel (its icon in the left bar).
  • Claude Code: the Claude icon in VS Code.

Let it edit files; say no to the rest. Let the agent edit files without asking each time:

  • Claude Code: accept edits;
  • Codex: Auto mode (it works in this folder);
  • Copilot: Keep the edits.

Say no if it wants to run git push, git reset or git clean, install a package, or change files outside toolkits/<your-toolkit-name>/.

How does the agent know the course's rules?

The agents read AGENTS.md (Claude Code through CLAUDE.md), and your prompt starts with the same rules. Agents can still make mistakes, so you review.

03

Send your prompt You do this

The rules first, then what to make.

Copy it from page 10 › Your prompt (your plan filled in), or copy this one and fill the orange blanks in the agent's box:

Rules: work only in toolkits/<your-toolkit-name>/ on my branch toolkit/<your-name-tag>. Do not change lab/ or any other folder or file, do not install or update packages, and do not push: I will push.
Read lab/docs/TOOLKITS.md and lab/docs/ai-kit/toolkit/PROMPT.md in this repository, then create my toolkit following them exactly. The folder name is exactly my toolkit name. Run the checks and commit only my folder.
Do not write any design: make the folder designs/ with only a short README.md that says how to add a design, and do not set defaultDesign in toolkit.ts. I will draw my designs in the app.

Toolkit name: ___
My idea: ___
Functions (and their attributes): ___
Algorithms: ___
Using Claude Code?

You can instead type /create-toolkit and answer its questions.

04

Review what it changed The agent does this You review

It writes your folder, runs the checks and commits.

The agent ends with a summary: your Functions, algorithms, designs, the checks and a commit. Then check yourself:

git status

nothing to commit, working tree clean, or only files under toolkits/<your-toolkit-name>/.

Something outside your folder changed? Ask the agent: “Undo only the changes to these files outside my toolkit folder, file by file, with git restore, then show git status.” Never let it undo everything at once.

Read the files too

Open your folder in the VS Code explorer: each step has a comment in plain English. Ask the agent to explain any rule you cannot explain yourself.

05

Try it in the app You do this

Run the app with your toolkit.

 
npm run dev

Open http://localhost:5173/?toolkit=<your-toolkit-name> › Create project with your toolkit chosen in the Toolkit list. Draw a small design with your Functions, then run your analyses in Analyse and your transforms in Transform.

Your toolkit has no design yet: the AI leaves designs/ to you. To add the one you drew: Add your own design.

The terminal is busy while the app runs. Open a second terminal with + for other commands; stop the app with Ctrl+C.

My toolkit is not there, or something is disabled
  • My toolkit is not in Open toolkit design…
  • A Function or algorithm is disabled
  • “localhost refused to connect”
06

Improve it You ask The agent changes

In plain words, one change at a time.

For example: “Make the Bedroom blue”, “The bed count ignores the upper level: fix it”. Paste any error message in full. Try every algorithm on a design whose answer you know.

07

Check and push You do this

You push, not the agent.

 
npm run check:toolkit -- -t <your-toolkit-name>

You should see, at the end

PASSED: toolkit "u123-hk-house" is ready.
The last line is what counts. FAILED: …: read the red message above it (Help).
npm run typecheck

the prompt again, with no red error lines.

git status

nothing to commit, working tree clean (the agent committed your folder).

It lists files of your folder: commit them yourself
git add toolkits/<your-toolkit-name>
git commit -m "feat(<your-toolkit-name>): first version of my toolkit"

Git says “Please tell me who you are”? Do this once.

git push

toolkit/<your-name-tag> -> toolkit/<your-name-tag>.

PASSED, the push went through, and a green ✓ appears beside your latest commit on GitHub.
