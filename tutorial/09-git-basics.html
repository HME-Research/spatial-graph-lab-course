Git basics

Git keeps the history of the repository. You type its commands in a terminal; GitHub Desktop does the same with buttons. This page starts with the terminal, then creates your branch, then lists everything else you need.

Your toolkit id

Type your initials and toolkit name once: every command on these pages fills in your id.

Your initials + toolkit name = your toolkit id

The naming convention: toolkit id = <initials>-<toolkit-name>, all lowercase, words joined with -, no spaces. Initials HK and toolkit Small library give hk-small-library. Your folder is toolkits/<toolkit-id>/ and your branch toolkit/<toolkit-id>. Type both below: every command and prompt on these pages fills in your id.

Toolkit id
<toolkit-id>
Folder
toolkits/<toolkit-id>/
Branch
toolkit/<toolkit-id>

Already pushed a branch with a different id? Keep using it: never rename a toolkit. Leave this empty to use the id built above.

Rule: lowercase letters, digits and -, starting with a letter. Remembered in this browser only. Without JavaScript, replace <toolkit-id> in the commands yourself.

The terminal

Where you type the commands.

01

What a terminal is

A window where you type commands instead of clicking.

A terminal (also called the command line) shows a prompt: a line that ends with >, % or $ and waits for you. You type a command, press Enter, the computer runs it and prints its answer, then shows the prompt again. A command always works in one folder, shown in the prompt: for git and npm that must be the repository folder.

Windows

This tutorial uses Command Prompt (prompt such as C:\Users\you\source\repos\spatial-graph-lab-course>). VS Code starts with PowerShell (prompt starts with PS) until you make Command Prompt the default: arrow next to the + in the terminal panel › Select Default Profile › Command Prompt, then open a new terminal (Set up › 07).

macOS

macOS has the Terminal app (Finder › Applications › Utilities). VS Code's terminal is the same thing inside VS Code (prompt ends with %).

02

Open it in the repository folder

The easiest way: VS Code's own terminal.

  1. Open the repository in VS CodeFile › Open Folder… (or File › Open Recent) › spatial-graph-lab-course.
  2. Open a terminalTerminal › New Terminal. It opens at the bottom, already in the repository folder.
  3. Check you are in the right folderThe prompt shows the folder name spatial-graph-lab-course. To be sure, print the folder, or ask git:

    Windows

    cd

    cd on its own prints the folder: a path ending in \spatial-graph-lab-course.

    macOS

    pwd

    It prints a path ending in /spatial-graph-lab-course.

    git status

    On branch …. “not a git repository” means the wrong folder: open the repository folder in VS Code and a new terminal.

03

Type or paste a command, press Enter

One command at a time; Ctrl+C stops one that keeps running.

  • Click in the terminal, then type the command, or copy it from these pages (the Copy button) and paste it: Ctrl+V or right-clickCmd+V. Press Enter.
  • A block of several lines: paste and run them one at a time if you are unsure; each line is one command.
  • Read the answer before the next command: “error”, “fatal” or “not recognized” means stop and look it up in Help.
  • Ctrl+C stops a command that keeps running, such as npm run dev — also on a Mac (Control, not Command).
  • ↑ brings back the previous command.

Your branch

Your own line of work: toolkit/<toolkit-id>.

04

Check the name is free

Nobody else in the class may use the same id.

Two students must not use the same id. Open the course repository's branches and type your initials in Search branches….

  • No toolkit/<toolkit-id> listed: the name is free.
  • It is listed and not yours: add a letter to your initials or change the toolkit name, above.
  • It is listed and yours (you pushed it earlier): keep it and switch to it instead of creating it again.

Free? Reserve it by pushing your branch as soon as you make it (step 05).

05

Create your branch

Once, before your first change; push it at once to reserve your toolkit id.

In the terminal, in the repository folder, run these four lines one at a time (get the latest main, make your branch from it, then push it):

git switch main
git pull
git switch -c toolkit/<toolkit-id>
git push -u origin toolkit/<toolkit-id>

Switched to a new branch 'toolkit/<toolkit-id>', then * [new branch] from the push. The branch name also shows at the bottom left of VS Code. This first push asks you to sign in (Signing in). Pushing the branch while it is still empty reserves your toolkit id: nobody else can create a branch with that name.

Push rejected (“Updates were rejected…”, “fetch first”)? The id is already taken by someone else's branch. Never git pull it: choose another id (above) and make that branch instead.

GitHub Desktop: Current branch › main, Fetch origin (then Pull origin if offered), then Current branch › New branch › name toolkit/<toolkit-id> › Create branch, then Publish branch.

Troubleshooting — common issues
“A branch named … already exists”
  1. You made it before: go to it (step 06), without -c.
“Cannot create ref due to creations being restricted”
  1. The branch name does not start with toolkit/: GitHub accepts only toolkit/… branches from students.
  2. Make the branch again with exactly toolkit/<toolkit-id> and push that one.
“Your local changes would be overwritten” on git switch main
  1. You changed files on another branch. Run git status to see which.
  2. Your toolkit's files: commit them on your branch first. Other files: put them back (Fixing common mistakes).
06

Go back to your branch later

Every working session, and on another computer.

git switch toolkit/<toolkit-id>

Switched to branch 'toolkit/<toolkit-id>' (or “Already on …”). On a new clone, git finds your pushed branch on GitHub by itself. Pushed from another computer since? Bring those commits in with git pull --no-rebase.

GitHub Desktop: Current branch › choose toolkit/<toolkit-id>.

Not sure which branch you are on? git branch lists them and marks the current one with *.

07Five ideas

IdeaMeaning
RepositoryThe project folder with its whole history. The course's copy is on GitHub; yours is on your computer (a clone).
BranchA separate line of work. main is the course's; yours is toolkit/<toolkit-id>. What you commit on your branch never changes main.
CommitA saved snapshot of the files you chose, with a short message. Commit whenever something works.
PushSends your branch's commits to GitHub, where your tutor sees them. Until you push, they are only on your computer.
PullFetches the new commits of the branch you are on from GitHub: on main, the course's updates; on your branch, commits you pushed from another computer. Course updates reach your branch only by merging (step 11).

09Before every commit

git status

On branch toolkit/<toolkit-id>, and under Changes to be committed only files under toolkits/<toolkit-id>/. On main, or other files there? Fix that first (below). A red modified: package-lock.json after npm install is not committed: put it back with git restore package-lock.json.

10Signing in to GitHub when you push

Your first push asks who you are (cloning does not: the repository is public). Accept the course invitation first (Set up › 06).

Windows

  1. A window Connect to GitHub opens: choose Sign in with your browser.
  2. In the browser, sign in and Authorize.
  3. Back in VS Code, the push continues. Windows remembers it.

macOS

  1. Push from VS Code's terminal: VS Code asks to sign in with GitHub. Choose Allow.
  2. In the browser, sign in and authorize VS Code, then return to VS Code; the push continues.
  3. If a terminal outside VS Code asks for a Username and Password: your GitHub password is not accepted there. Press Ctrl+C and push from VS Code's terminal, or with GitHub Desktop (Publish branch).

GitHub Desktop: sign in once in File › Options › AccountsGitHub Desktop › Settings… › Accounts.

11Get the course's updates (changes on main)

Now and then your tutor changes the app and pushes it: main on GitHub gets new commits. Your branch does not get them by itself; you bring them in by merging main into your branch. Your toolkit folder stays as it is.

  1. Commit your own work first 
    git status

    nothing to commit, working tree clean. Otherwise commit your toolkit first (git add, git commit: the commands), or put back files outside your folder (below).

  2. Get the new main and merge it into your branch 
    git switch main
git pull
git switch toolkit/<toolkit-id>
git merge main

    “Fast-forward” or “Merge made by the 'ort' strategy”, or “Already up to date”.

    If an editor opens for the merge message: in a VS Code tab, close the tab (the message is fine as it is); in the editor called Vim (a ~ on every line), type :wq and press Enter.

  3. Install what the course added 
    npm install
  4. Run your checks again (an update can show a new message about your toolkit): 
    npm run check:toolkit -- -t <toolkit-id>
npm run typecheck
  5. Push your updated branch 
    git push

GitHub Desktop: Fetch origin › Current branch: your branch › Branch › Update from main › Push origin. Then run npm install and the checks in the terminal.

Troubleshooting — common issues
“CONFLICT (content): Merge conflict in …”
  1. Run git merge --abort: your branch is back as it was.
  2. Ask your tutor, with the message.

Never edit files outside your folder to make a conflict go away.

“Your local changes to the following files would be overwritten”
  1. You have changes that are not committed.
  2. Your toolkit's files: commit them on your branch. Other files: undo them (below).
  3. Run the update steps again.
“fatal: invalid reference: toolkit/…”
  1. The branch name is wrong (a typo, or another id).
  2. Run git branch to list your branches, and use exactly the name shown.
“fatal: Need to specify how to reconcile divergent branches” on git pull of main
  1. You committed on main earlier. Follow I committed on main, then run the update steps again.

12Fixing common mistakes

I changed a file outside my folder

Put it back as it was (this throws away your change to that file only):

git restore --staged path/to/the/file
git restore path/to/the/file

A new file outside your folder (listed as untracked): delete it, or move it into your folder.

I committed on main

GitHub refuses to take it, so nothing is lost. First commit or put back anything git status lists. Then bring the commits into your branch and put your main back to the course's (this also works when git pull on main says “divergent branches”):

git switch toolkit/<toolkit-id>
git merge main
git branch -f main origin/main
git push

No branch yet (“invalid reference” on the first line)? Make it from your main instead:

git switch -c toolkit/<toolkit-id>
git branch -f main origin/main
git push -u origin toolkit/<toolkit-id>

If the merge shows a CONFLICT or the commits changed files outside your folder, run git merge --abort and ask your tutor instead of improvising.

Git asks me to sign in, or says “permission denied”
  1. Accept the course invitation first (Set up › 06).
  2. Sign in as described in Signing in to GitHub.
Git opened a strange text editor

That is a merge message after git pull or git merge. In the editor called Vim (a ~ on every line): type :wq and press Enter. In VS Code: save and close the tab.

“Updates were rejected because the remote contains work that you do not have”
  1. On your first push of this branch: the id is already taken by someone else's branch. Never pull it: choose another id and make that branch instead (step 05).
  2. You pushed this branch before (for example from another computer): run git pull --no-rebase, then git push.
Push refused: “protected branch”, “rule violations” or “cannot update this protected ref”
  1. You are pushing main. Your work belongs on your branch: see “I committed on main” above.
Push refused: “Cannot create ref due to creations being restricted”
  1. The branch name does not start with toolkit/. Make the branch again with exactly toolkit/<toolkit-id> (step 05).
“fatal: Need to specify how to reconcile divergent branches”
  1. On your branch: use git pull --no-rebase instead of git pull.
  2. On main: you committed on main; see “I committed on main” above.
