What a terminal is

A window where you type a command and press Enter.

In VS Code: Terminal › New Terminal. It opens at the bottom, in the folder VS Code has open. Its prompt, a line ending in > (Windows) or % (Mac), waits for you. Paste one command, press Enter, read the answer, then the next.

Windows

macOS

Keys, and the folder the terminal is in
  • Paste: Ctrl+V or right-clickCmd+V. ↑ brings back the previous command.
  • Ctrl+C stops a command that keeps running, such as npm run dev, also on a Mac.
  • The folder: Windows cd alone prints it (cd with a folder after it goes there); Mac pwd. It must end in spatial-graph-lab-course.
  • “error”, “fatal” or “not recognized”: look it up in Help.
Other ways to open a terminal in a folder (optional)

Windows

Windows 11: in File Explorer, right-click the folder › Open in Terminal. It opens PowerShell: type cmd and press Enter first.

macOS

Finder: right-click the folder › Services › New Terminal at Folder. Not there? Turn it on once in System Settings › Keyboard › Keyboard Shortcuts › Services › Files and Folders.

5

Five ideas

Repository, branch, commit, push, pull.
IdeaMeaning
RepositoryThe course folder with its whole history: on GitHub, and as a copy (a clone) on your laptop.
BranchA separate line of work. main is the course's; yours is toolkit/<toolkit-id>. Your commits never change main.
CommitA saved snapshot of the files you chose, with a short message.
PushSends your branch's commits to GitHub. Until you push, they are only on your laptop.
PullFetches commits from GitHub into the branch you are on.

Commands

Not a sequence: look up the one you need. Run every command in VS Code's terminal, in the course folder.

$

git status

Which branch you are on, and what changed.

 
git status

first line On branch …; then green files (in the next commit), red files (changed, not added), or nothing to commit, working tree clean.

Common problems
  • “not a git repository”
  • files outside my folder are listed
$

git pull

Get the newest commits of the branch you are on from GitHub.

 
git pull

“Already up to date.” or a list of updated files.

Used on main before you make your branch (page 6). On your own branch, use git pull --no-rebase --no-edit to get what you pushed from another computer.

Common problems
  • “Need to specify how to reconcile divergent branches”
  • “Your local changes … would be overwritten”
$

git switch

Go to a branch that already exists.

 
git switch toolkit/<toolkit-id>

Switched to branch 'toolkit/<toolkit-id>', and VS Code's bottom left shows it.

Common problems
  • “invalid reference” (a typo, or the branch is not made yet)
  • “Your local changes … would be overwritten”
$

git switch -c

Create a new branch and go to it.

 
git switch -c toolkit/<toolkit-id>

Switched to a new branch 'toolkit/<toolkit-id>'.

-c = “create it first”. You do this once, on page 6.

Common problems
  • “A branch named … already exists”: use git switch without -c.
$

git add

Choose what goes into the next commit: your folder.

 
git add toolkits/<toolkit-id>

nothing printed. git status then lists your files in green.

Only your folder. Never git add . or git add -A: they add files outside your folder.

$

git commit -m

Save a snapshot of what you added, with a short message.

 
git commit -m "feat(<toolkit-id>): <what-changed>"

[toolkit/<toolkit-id> 1a2b3c4] feat(…): … and the number of files changed.

How to write the message

feat(…): for something new, fix(…): for a correction, then a few words, e.g. feat(hk-small-library): seat count analysis.

Common problems
  • “Please tell me who you are”
  • I committed on main
  • An editor with ~ lines opened (you forgot -m)
$

git push

Send your branch's commits to GitHub.

 
git push

toolkit/<toolkit-id> -> toolkit/<toolkit-id>, or “Everything up-to-date” if there was nothing new.

Common problems
  • “Permission denied” / 403
  • “GH013 … rule violations”
  • “GH007 … email privacy”
  • “src refspec … does not match any”
$

git push -u

The first push of a new branch.

 
git push -u origin toolkit/<toolkit-id>

* [new branch]. -u remembers GitHub (origin) as the place this branch goes, so later a plain git push is enough.

“rejected” or “Everything up-to-date” on this first push? Someone already has this name: choose another (page 6). Never pull their branch.

$

git pull --no-rebase --no-edit origin main

Bring the course's updates into your branch, without leaving it.

 
git pull --no-rebase --no-edit origin main

a list of changed files, or “Already up to date.”

origin main = the course's main on GitHub; it is merged into the branch you are on. --no-edit keeps an editor from opening. Commit your work first; afterwards run npm install and your check (page 11).

Common problems
  • “CONFLICT”
  • “Your local changes … would be overwritten”
$

git restore

Put one file back as it was; --staged takes it out of the next commit.

 
git restore package-lock.json

nothing printed; git status no longer lists the file.

For another file, type its path as git status shows it. If it is green (added), first:

git restore --staged <path-of-the-file>

One file at a time. Never git restore ., git checkout -- ., git reset --hard or git clean: they also throw away your toolkit work.

$

git log --oneline

Your latest commits, one per line.

 
git log --oneline -5

five lines such as 1a2b3c4 feat(…): seat count analysis, newest first.

$

git diff

Which files changed since your last commit.

 
git diff --stat

one line per changed file with + and -: only files in your folder. Without --stat it shows every changed line (press q to leave).

Signing in to GitHub when you push

Once, on your first push.

Windows

  1. A window Connect to GitHub opens: choose Sign in with your browser.
  2. In the browser, sign in and Authorize. The push continues; Windows remembers it.

macOS

  1. Push from VS Code's terminal: VS Code asks to sign in with GitHub. Choose Allow.
  2. In the browser, sign in and authorize VS Code; the push continues.

A terminal asks for a Username and Password? Help.

“Permission denied” or 403: accept the course invitation first (Set up › 06).

!

VS Code's Source Control panel

The branch icon in VS Code's left bar. The course uses the terminal instead.

Careful with its buttons. Its Commit button offers to stage all changes, which commits package-lock.json and other files outside your folder (a red ✗ on GitHub). Sync Changes and Publish Branch push for you. If you use it, stage only your folder: right-click each file under toolkits/<toolkit-id>/ › Stage Changes, and never answer “Always” to “stage all”.

Already committed everything? Help.
